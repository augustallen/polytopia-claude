Found two high-priority failure paths. This was a static review; the available `python` command is a Store alias, so I couldn’t rerun tests. No files changed.

1. **[P1] Action timeout recovery is unsafe** — [runner.py:247](harness/polytopia_bridge/runner.py:247), [client.py:95](harness/polytopia_bridge/client.py:95). A missing result becomes a synthetic rejection, then execution continues on the same connection. After a socket timeout, Python’s buffered socket reader can raise `OSError: cannot read from timed out object`; additionally, `expect()` loses its locally skipped messages when an exception escapes. **Fix:** terminate the run as `timeout` and close the connection on action-result timeout. Continuing safely would require explicit resynchronization and timeout-safe buffering. Test with a real socket and a delayed result.

2. **[P1] Automatic actions can retry forever** — [runner.py:338](harness/polytopia_bridge/runner.py:338), [runner.py:367](harness/polytopia_bridge/runner.py:367), [runner.py:274](harness/polytopia_bridge/runner.py:274). Rejected triggers and captures ignore the result. If the bridge keeps advertising the same action, each rejection produces another state and another identical attempt. Trigger handling bypasses budgets, and capture sweeping remains enabled even after budget exhaustion. **Fix:** bound repeated attempts against an unchanged state; suppress a failed optional capture, and terminate with diagnostics when a mandatory trigger cannot progress. Test repeated rejections and accepted commands that leave state unchanged.

3. **[P2] Empty legal lists wait for an unsolicited change that may never happen** — [runner.py:329](harness/polytopia_bridge/runner.py:329). The bridge suppresses unchanged states at `Plugin.cs:615`. An idle state with no legal actions therefore stalls until the default 900-second timeout. `LegalActions.Enumerate()` does not guarantee a nonempty result, including when trigger choices fail validation. **Fix:** treat this as an unsupported/stuck state, with bounded diagnostic recovery or immediate termination. Don’t passively await another state.

4. **[P2] The action cap does not constrain an existing plan** — [runner.py:342](harness/polytopia_bridge/runner.py:342). The cap is checked only when `steps` is empty. A sufficiently long plan can execute beyond `max_actions_per_turn`. **Fix:** enforce the cap before each ordinary planned action, clear remaining steps, and transition to bounded turn completion. Test a plan longer than the cap.

5. **[P2] CLI launch failures bypass planner fallback** — [claude_stream.py:200](harness/polytopia_bridge/claude_stream.py:200). `Popen()` is outside error translation. Missing executables, access failures, and Windows command-line errors raise `OSError`, while `TurnPlanner` catches only `PlannerError`. The game loop exits by exception instead of using its fallback. **Fix:** translate launch errors into `PlannerError`; test `FileNotFoundError` and representative Windows launch errors.

6. **[P2] Timeout termination is not guaranteed to unblock pipes** — [claude_stream.py:185](harness/polytopia_bridge/claude_stream.py:185). `taskkill` has no timeout, its status is ignored, and there is no direct-kill fallback. If it fails, the main thread can remain blocked on stdout indefinitely. Cleanup also omits a final wait after killing and explicit pipe closure. **Fix:** bound `taskkill`, check failure, use `proc.kill()` as fallback, reap the process, and close pipes in cleanup. Add subprocess-level timeout tests; current tests never exercise this function.

7. **[P2] Prompt writing and stdout reading are serialized** — [claude_stream.py:222](harness/polytopia_bridge/claude_stream.py:222). The parent writes the entire prompt before draining stdout. If the CLI emits enough startup output before finishing stdin consumption, both pipes can fill and block until timeout. **Fix:** write and close stdin in a worker while the main thread immediately drains stdout. Test a child that fills stdout before reading a prompt larger than pipe capacity.

8. **[P2] Empty plans contradict the documented replan convention** — [runner.py:357](harness/polytopia_bridge/runner.py:357). `actions: []` is explicitly accepted by the planner, and the instructions say omitting `end_turn` requests another call. The runner instead ends the turn. **Fix:** either reuse the current state and replan within the remaining call budget, or explicitly define an empty plan as passing in the prompt and tests.

9. **[P2] `PopGrowth` does not match the promised reward policy** — [runner.py:200](harness/polytopia_bridge/runner.py:200). `"popgrowth".startswith("population")` is false. If offered `PopGrowth` and `BorderGrowth`, the policy selects borders despite documenting support for both population spellings. **Fix:** normalize explicit aliases before ranking. Test both population names and both offer orders.

10. **[P2] Capturing the capital makes the observation claim it was never found** — [observe.py:180](harness/polytopia_bridge/observe.py:180). After capturing the enemy capital while other enemy cities remain, `enemy_capital()` returns `None`; the objective then instructs scouting for the “NOT FOUND YET” capital. **Fix:** distinguish an undiscovered capital from one already captured, retaining discovery history or exposing original capital ownership. Test the post-capital-capture state with surviving enemy cities.
